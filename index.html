Busymate AI SDK for Linux

What it does

A C library on GTK4 and WebKitGTK 6.0, built with Meson, with GObject Introspection data (Busymate-1.0) for Python, GJS, Vala and Rust. BusymateBridge provides the identity wire v2 (immutable build 2.0.0) with byte-compatible envelopes to the Android, iOS and JavaScript hosts; BusymateMicrophone is the microphone adapter 1.0.0 (wire 1). The sending frame's origin is read in an isolated WebKit script world; web-process crashes reload the chat and send restored.

GTK4 + WebKitGTK host

Install the bridge and the optional microphone adapter on your WebKitWebView once, before the first load, then load your chat URL on channel=desktop_sdk.

Identity bridge v2

Connect get-account and mint signals; answer mint with busymate_mint_request_return_token() from your own HTTPS backend.

Bindings via GI

pkg-config busymate-ai-sdk-1 and the Busymate-1.0 typelib; a Meson wrap keeps the version pinned.

Example app

busymate-sdk-example is a GTK4 app with a Settings dialog (chat URL, locale, origins, guest vs identified mode, microphone, close callbacks) and an Events pane.

Install

Build from source with Meson, as a pinned subproject or a system install. Ubuntu 24.04: apt install meson ninja-build gcc pkg-config libgtk-4-dev libwebkitgtk-6.0-dev libjson-glib-dev libsoup-3.0-dev gobject-introspection libgirepository1.0-dev.

  1. As a Meson subproject, add subprojects/busymate-ai-sdk-linux.wrap and depend on busymate-ai-sdk-1.

    [wrap-git]
url = https://github.com/serebano/busymate-ai-sdk-linux.git
revision = 1.0.2
depth = 1

[provide]
busymate-ai-sdk-1 = busymate_dep

# meson.build
# dependency('busymate-ai-sdk-1', default_options: ['example=false', 'tests=false'])

  2. Or install system-wide; the release also attaches the source tarball and an Ubuntu 24.04 x86_64 build with SHA256SUMS.

    git clone --branch 1.0.2 --depth 1 https://github.com/serebano/busymate-ai-sdk-linux.git
cd busymate-ai-sdk-linux
meson setup _build -Dexample=false && meson compile -C _build && sudo meson install -C _build

  3. Install both pieces on your web view before the first load.

    #include <busymate/busymate.h>

const char *origins[] = { "https://support.acme.com", NULL };
BusymateBridge *bridge = busymate_bridge_new ("acme", origins);
g_signal_connect (bridge, "get-account", G_CALLBACK (current_account_or_null), app);
g_signal_connect (bridge, "mint", G_CALLBACK (ask_your_backend), app);
busymate_bridge_install (bridge, web_view);

const char *chat[] = { "https://acme.busymate.ai", NULL };
BusymateMicrophone *microphone = busymate_microphone_new (web_view, chat);

webkit_web_view_load_uri (web_view, "https://acme.busymate.ai/?channel=desktop_sdk");

Identity linking and the microphone

Both bridges are installed by your app before the chat's first load. Your native app release is what installs or upgrades native SDK code; the hosted chat updates independently.

Identity linking

BusymateBridge (wire v2, build 2.0.0) emits get-account and mint signals; your app answers with the current account or NULL and with a fresh assertion from your own HTTPS backend. No v1 bridge is provided on Linux. Read identity.md.

Microphone

BusymateMicrophone (wire 1, adapter 1.0.0) runs the permission step only when the user taps the chat's microphone or voice control and grants WebKit audio capture for allowed origins only, including PipeWire, Flatpak and Snap notes. Read microphone.md.
